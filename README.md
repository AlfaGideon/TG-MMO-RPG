# 🌑 Shadow Lands — Telegram MMORPG

Игровой движок и админ-панель на Python. `index.html` поднимает Python в
браузере (Pyodide) и отдаёт ему игровую логику и рендер страниц; настоящий
интерактив разметки (кисть по карте, drag-and-drop локаций, живые таймеры)
работает на обычном статическом JS — `webapp/static/interactions.js`.
Каждый инструмент делает то, для чего подходит: Python — правила игры и
HTML-строки, JS — события мыши/касаний и DOM, которые Python в Pyodide
дёргает медленнее и не может выполнить из вставленного через `innerHTML`
`<script>` (это специально запрещено спецификацией браузеров).

> **Почему Pyodide «не показывает» другие языки?** Pyodide — это CPython,
> собранный в WebAssembly: он исполняет **только Python** (это свойство, а не
> поломка). Для JS / C++ / Ruby в панели есть раздел **«Песочница кода»**
> (`webapp/pages/code.py`), где каждый язык исполняется своим рантаймом прямо
> в браузере: JS — нативным движком, C++ — интерпретатором JSCPP, Ruby —
> официальным `ruby.wasm`. Тяжёлые рантаймы грузятся лениво, при первом
> запуске, и не замедляют старт панели.

## 🖥 Запуск админки (превью в Arena / локально)

Открой **`index.html`** через preview или локальный сервер:

```bash
python3 -m http.server 8000     # затем http://localhost:8000/index.html
```

> Через `file://` не заработает — модули подгружаются по fetch.

Дальше в панели: вкладка **🤖 Бот** → вставь токен от [@BotFather](https://t.me/BotFather)
→ **Запустить бота**. Бот начнёт отвечать в Telegram, пока открыта вкладка.

### Если бот не стартует

Telegram с осени 2025 отклоняет запросы с браузерным User-Agent. В разделе
**🤖 Бот → Транспорт** переключи режим с «Напрямую» на любой прокси-релей
(corsproxy / allorigins / codetabs) или укажи свой и нажми «Применить».
Для постоянной работы 24/7 используй серверный запуск (см. ниже).

### После правки любого модуля `engine/` или `webapp/`

Обнови собранный пакет модулей, иначе холодный старт панели возьмёт
устаревший код из `webapp/bundle.json`:

```bash
python3 tools/build_bundle.py
```

Эта же команда **автоматически обновляет `?v=` для `admin.css` и
`interactions.js` в `index.html`** (версия = хэш содержимого файла).
GitHub Pages и браузер кешируют статику агрессивно; раньше версия была
зашита вручную, поэтому правки CSS «не приживались» — чтобы дизайн
обновился, достаточно отредактировать файл и снова прогнать сборку.

`tests/test_wiring.py` проверяет, что `bundle.json` не отстал от
`modules.json` — забытый билд ловится тестами до того, как попадёт в прод.

Правила модульности (их стережёт `tests/test_wiring.py`):
`engine/` не импортирует ни `js`, ни `webapp`; `pages/*` только возвращают HTML-строки
и не трогают DOM; ни один файл не длиннее **500 строк**; каждый `data-act` из разметки
обязан иметь обработчик в `actions/`.

**Паритет стеков обязателен.** Новая механика делается сразу для обоих:
`engine/` + `webapp/` (стек A) и `core/` + `bot/` + `admin/` (стек B).
Если паритет отложен — это фиксируется в реестре `tests/test_parity.py`
с причиной, иначе тест падает. Так разрыв виден сразу, а не всплывает
через месяц.

### ⚠️ Два стека — куда класть новую возможность

В репозитории живут **два независимых стека**, и это главная ловушка проекта:

| | Стек A — GitHub Pages | Стек B — сервер |
|---|---|---|
| Код | `engine/` + `webapp/` | `bot/` + `admin/` + `core/` |
| Запуск | `index.html` через Pyodide | `launch.py` (aiogram + FastAPI) |
| Хранилище | `localStorage` браузера | SQLite/Postgres |
| Что видно на `alfagideon.github.io` | **только этот** | ничего |

Сайт грузит **ровно то, что перечислено в `modules.json`**, а там только
`engine/` и `webapp/`. Поэтому возможность, добавленная лишь в `core/`
или `bot/`, на GitHub Pages физически не появится — файлы просто не
скачиваются. Именно так вышло с обновлением 8: код был написан, тесты
проходили, а в панели ничего не менялось.

**Правило:** новая игровая механика должна попасть в `engine/`, новый
раздел панели — в `webapp/pages/` + `webapp/actions/`, и оба — в
`modules.json`. Это проверяет `tests/test_wiring.py`: он падает, если
модуль лежит в репозитории мимо манифеста или страница не подключена
в боковое меню.

### Как модули взаимодействуют

```
index.html ──fetch .py──> Pyodide FS ──> webapp/boot.py
                                             │
                    webapp/app.py ───────────┴──── webapp/pages/*.py (HTML-строки)
                          │
          ┌───────────────┼────────────────┐
   webapp/telegram.py  engine/storage.py  webapp/dom.py
          │                   │
   webapp/transport.py   engine/game.py ──> combat / world / rules / texts / data
          │
   api.telegram.org
```

`engine/` ничего не знает ни про браузер, ни про Telegram — его можно
подключить к серверному боту без изменений.

## 🎮 Что умеет игра

- **10 классов** из коробки, новые добавляются из админки без правки кода
- Случайные стартовые статы (−10 %…+20 %) с 10 попытками переката
- Шесть школ магии: у героя от нуля до двух предрасположенностей
- Прокачка со своим приростом статов у каждого класса, экипировка по слотам
- Бесшовный мир: локации по 100 клеток, **новые добавляются из админки** —
  со связной генерацией, автошвами к соседям по сетке мира и защитой от
  коллизий координат; в боте — 🌍 карта мира с туманом войны и 🏠 travel
  в посещённые безопасные локации
- Движение в 8 направлениях, осмотр клетки, ASCII-карта
- Пошаговый бой: атака, защита, умение, побег, криты — с учётом экипировки
- **Живой мир**: мобы ходят по карте, держат популяцию и респавнятся
- **Уникальный лут**: у каждого предмета свой ID со значком происхождения
- **История предметов**: кто добыл, у кого побывал, за сколько ушёл
- **Аукцион** между игроками и скупщик-NPC
- **Реликвии** в единственном экземпляре и праздничные трофеи
- **Крафт и заточка** у NPC-ремесленников, сундуки, лавка, зелья, отдых

### 🆔 Уникальные предметы

Предмет в базе — это *шаблон*. Каждый выпавший, купленный или скрафченный
экземпляр — отдельная строка `item_instances` со своим коротким ID и
собственными статами. **Перед ID стоит значок способа получения**, поэтому
происхождение вещи видно с одного взгляда:

| Значок | Откуда | Значок | Откуда |
|---|---|---|---|
| ⚔️ | выбито в бою | 🏪 | куплено в лавке |
| 📦 | найдено в сундуке | 🔁 | прошло через аукцион |
| 🕳 | добыто в подземелье | 🎄 | праздничный трофей |
| 🔨 | изготовлено | 🌟 | единственное в мире |
| 📜 | награда за задание | 🛠 | выдано администратором |

```
⚔️IT-D55CA5C1   Добротный Кинжал теней   ← выбит из моба
🔨IT-E6ED3800   Выверенный Стальной меч  ← скован в кузнице
🔁IT-D55CA5C1   тот же кинжал после продажи на аукционе
```

Значки особых меток важнее исходного источника: реликвия всегда светится
🌟, праздничная вещь — 🎄, а торгованная — 🔁. Ресурсов и расходников это
не касается: они складываются в стопки и своего ID не имеют.

Что именно катается у экземпляра:

| Что катается | Как |
|---|---|
| **Качество** | 100 % ± `stat_variance` шаблона (по умолчанию ±15 %), треугольное распределение — середина вероятнее краёв |
| **Статы** | базовое значение × качество × множитель редкости, плюс независимый джиттер ±6 % на каждый стат |
| **Редкость** | небольшой шанс (≈6 % + удача) получить ступень выше шаблонной |
| **Префикс** | по качеству: «Ржавый» → «Крепкий» → «Мастерский» → «Легендарный» |

Удача персонажа слегка смещает броски вверх и повышает шансы дропа.
Расходники и материалы не катаются — они складываются в стопки.

### 📖 История предмета

У каждого именного экземпляра ведётся летопись: кто добыл, из кого выбил,
у кого побывал, за сколько уходил. Поэтому вещь, купленная на аукционе,
приходит к новому владельцу **не пустой**:

```
⚔️ 28.07 выбит в бою — Аня (Теневой призрак)
📢 28.07 выставлен на аукцион — Аня за 150🪙
🔁 28.07 продан на аукционе — Боря за 150🪙 (куплен у Аня)
⚡ 29.07 заточен — Боря до +3
```

История видна игроку в карточке предмета и администратору на странице
экземпляра. Чем больше сделок прошла вещь, тем выше её оценка на аукционе.

### ⚖️ Аукцион

Игроки продают друг другу именные вещи по принципу «купить сразу»:

- продавец выбирает цену из готовых вариантов (от «💸 быстро» до
  «🤑 очень дорого»), опираясь на оценку аукциона;
- пока лот висит, вещь физически лежит на витрине, а не в сумке;
- покупателю уходит предмет со всей историей, продавцу — деньги за
  вычетом 5 % комиссии;
- непроданный за сутки лот сам возвращается владельцу;
- одновременно можно держать до 5 своих лотов.

**Скупщик Молчун** подстраховывает рынок: выкупает вещь мгновенно
(примерно за 55 % оценки) и перевыставляет её с наценкой. Деньги приходят
сразу, а предмет не пропадает из мира и сохраняет летопись.

### 🌟 Реликвии и 🎄 праздничные вещи

- **Единственные в мире** существуют ровно в одном экземпляре. Как только
  реликвия кому-то досталась, она исчезает из всех таблиц лута — второй
  такой не будет. Вернуть её в розыгрыш можно в админке
  (**Контент → 🎄 События**).
- **Праздничные** падают, только пока включено соответствующее событие
  (зимняя стужа, праздник жатвы, ночь духов). Выключил событие — вещь
  снова недоступна, но у тех, кто успел, она осталась с меткой 🎄.

### 🔮 Предрасположенность к магии

Шесть школ: 🔥 огонь, ❄️ лёд, ⚡ гроза, 🌑 тьма, 🌿 природа, ✨ свет.
При создании героя бросается дар — **от полного его отсутствия до двух
школ сразу**:

| Ступень | Множитель | Метка |
|---|---|---|
| Искра | ×0.6 | ◦ |
| Дар | ×1.0 | • |
| Сильный дар | ×1.4 | ✦ |
| Талант | ×1.8 | ✸ |

Шансы зависят от класса: у мага и некроманта дар почти гарантирован (и
часто двойной), у воина с берсерком магия — редкая случайность. Класс
также склонен к своим школам: некроманту вчетверо чаще выпадает тьма,
жрецу — свет и природа.

Дар не заменяет статы, а усиливает умение в бою и работает вместе с
магическими фокусами (жезл пламени, посох инея и т. п.): если школа
предмета совпадает с даром героя, бонусы складываются.

### 🎲 Случайные стартовые статы

Герой больше не рождается с одинаковым для всех набором. Статы катаются
от базы класса в диапазоне **−10 %…+20 %**, и при создании даётся
**10 попыток переката**:

```
🔮 Тестер — Маг
👍 Хороший бросок — 107% от базы класса
💪 Сила: 5      🧠 Интеллект: 18 (+2)   ❤️ HP: 88 (+8)
🏃 Ловкость: 9  🛡 Выносливость: 8      💙 MP: 132 (+12)
🎲 Осталось попыток: 7
```

Перекат заменяет текущий бросок — вернуться к предыдущему нельзя, так что
решать надо на месте. Принял бросок или потратил все попытки — статы
фиксируются навсегда. Магический дар бросается один раз и перекатом
не меняется: с чем родился, с тем и живёшь.

Так два «Кинжала теней» из одного моба всё равно разные:

```
IT-34936718   104%   rare    урон 11   ловк 3   Добротный Кинжал теней
IT-4FF76CDE   101%   epic    урон 12   ловк 4   Крепкий Кинжал теней
IT-F9E438EB    96%   rare    урон  9   ловк 3   Добротный Кинжал теней
```

### 🔨 Крафт, ⚗️ алхимия и заточка

На карте стоят NPC-ремесленники трёх типов — **кузнец** (оружие и броня),
**алхимик** (зелья и эликсиры) и **ювелир** (аксессуары и магические
фокусы). У каждого свои рецепты.

**Алхимия** работает на реагентах, которые сыплются со всех мобов
понемногу: уголь саламандры, вечный лёд, громовая соль, слеза тьмы,
корень мандрагоры, пыльца рассвета. Из пустого флакона и травы гонится
дистиллят — основа всех зелий. Дальше варятся эликсиры характеристик
(силы, ловкости, прозрения, стойкости, удачи), настой полного исцеления и
философский раствор.

- **Крафт** — тратятся материалы и золото, на выходе снова *уникальный*
  экземпляр со свежими статами. У сложных рецептов есть шанс брака.
- **Заточка** — существующий предмет улучшается за золото и материалы,
  добытые гриндом. Каждый уровень поднимает статы на долю от базы;
  при неудаче уровень сохраняется, но ресурсы сгорают.

Рецепты, ингредиенты и правила заточки настраиваются в
**Контент → 🔨 Крафт** без правки кода.

### 👣 Живой мир: популяция мобов

Мобы больше не «прибиты» к клетке навсегда:

- в локации держится ровно `population` живых экземпляров каждого моба;
- убили одного — новый появится через `respawn_seconds`, но **сверх лимита
  никто не заспавнится**;
- живые мобы ходят по проходимым клеткам своей локации;
- **слабый моб может забрести в локацию уровнем выше, сильный к слабым —
  нет**: переход разрешён, только если `min_level` цели не ниже
  `min_level` его домашней локации;
- моб, с которым идёт бой, стоит на месте до конца схватки.

Мир тикает раз в 20 секунд фоновой задачей бота
(`bot/runner.py` → `core/spawns.tick`). Текущее состояние видно в
**Контент → 👣 Популяция**.

### 🏪 Лавка и 🎒 инвентарь

Списки предметов оформлены одинаково (общий модуль `engine/itemui.py`):

- в инлайн-кнопках **только эмодзи** — номер `1️⃣…🔟` и иконка предмета,
  по 5 в ряд; никакого текста в кнопках списка;
- что скрыто за номером — написано в тексте сообщения: название, тип,
  редкость и цена;
- нажатие номера открывает **карточку**: бонусы расписаны словами
  (⚔️ Урон +10, 🏃 Ловкость +3) и появляются кнопки действий;
- больше 10 предметов — включается листалка `⬅️ 2/3 ➡️`, а возврат из
  карточки ведёт на ту же страницу.

| Где | Кнопки в карточке |
|---|---|
| 🏪 Лавка → 🛒 Купить | **Купить** (прячется, если не хватает золота) |
| 🏪 Лавка → 💰 Продать | **Продать** — остаёмся в лавке |
| 🎒 Инвентарь | **Надеть** / **Снять**, для зелий — **Использовать**, плюс **Продать** и **Выбросить** |

У лавки две вкладки, активная помечена точками: `• 🛒 Купить •` / `💰 Продать`.

  - 🌐 *Сетка мира* — раскладка 10×10, drag&drop-переезд, пересшивка дверей;

  - 🌋 *Катаклизмы* — что бушует, чем ударить, автостихии, летопись

  - 🆔 *Экземпляры* — все именные вещи с ID, происхождением, качеством,

## ♻️ Живой мир

### Респавн: мир больше не одноразовый

Раньше мир был *исчерпаем*: выбитая тварь исчезала навсегда, вскрытый сундук
не возвращался. За вечер игры карта пустела, и задания на охоту стали бы
невыполнимыми.

Теперь убийство не стирает тварь, а ставит на клетку метку времени
(`Cell.mob_at`). `respawn.tick()` вызывается на шаге игрока — там же, где
проверяются катаклизмы, — поэтому фоновые задачи не нужны: мир оживает
тогда, когда в него кто-то смотрит.

- **Твари** возвращаются на свою клетку. Если там стоит игрок, возвращение
  откладывается — тварь не появляется под ногами.
- **Сундуки** возвращаются на *случайную* клетку локации, иначе игроки
  заучили бы точки и ходили по кругу.
- **Задержки** по типу локации: `dangerous` 15 мин, `dungeon` 30, `boss` 45.
  В безопасных землях — `0`, то есть никогда. Всё настраивается в панели.
- Респавн не конфликтует с ордой катаклизма: пока бушует бедствие,
  популяция всё равно держится на ×2 от мирной нормы.

### Игроки видят друг друга

До этого в MMO каждый был один: карта показывала тайлы, туман и себя.
Соседи по миру существовали только в админ-панели.

- на карте — 🔵 в клетке с другим героем (**только в изученных клетках**:
  иначе карта выдавала бы содержимое тумана);
- в описании клетки — «🔵 Здесь же: Мара (ур. 4)»;
- в шапке карты — счётчик героев поблизости.

Три вида, и все проверяются по тому, что игра уже считает, — новых счётчиков

## 👣 Характеры тварей

Раньше все мобы были неотличимы: стояли на клетках вечно и ждали, пока на
них наступят. Теперь у каждого вида свой нрав — поле в «Контент → Мобы»:

| Нрав | Поведение |
|---|---|
| 🪨 Пассивная | ждёт на месте, как раньше |
| 🛡 Территориальная | не сходит с клетки, но бросается на подошедшего вплотную |
| 🐺 Охотник | бродит по округе и сам идёт на игрока за две клетки |

Катаклизм не отменяет характеры, а накладывается сверху: в бедствие смелеют
все. Брожение и самостоятельные нападения можно выключить в панели —
**Мир → ♻️ Жизнь мира**.

При брожении тварь тащит за собой метку респавна: иначе покинутая клетка
«родила» бы ещё одну и популяция поползла бы вверх.

## 🎒 Два инвентаря: сумка и карман

Как в Таркове: игрок сам решает, что берёт риском, а что прячет.

| | 🎒 Сумка | 🔒 Защищённый карман |
|---|---|---|
| Размер | безразмерная | 5 ячеек (👑 VIP: 8) |
| При гибели | половина вещей выпадает в надгробие | **цел полностью** |
| Где трогать | всегда | только в безопасных землях |

Карман намеренно **меньше** сумки — иначе выбора нет и все просто прятали бы
всё. Перекладывать можно лишь в Погосте: иначе игрок убирал бы добычу прямо
перед смертью и риск исчезал бы вовсе.

Что ещё стоит знать:

- **надетое не теряется** — снимать с трупа собственную экипировку было бы
  слишком сурово, а риск и так есть;
- вещь, убранная в карман, автоматически **снимается с героя**: спрятанное
  нельзя носить;
- выпавшие вещи ждут в надгробии вместе с золотом — дошёл, забрал всё.
  С чужой могилы достаётся половина и золота, и вещей.

**👑 VIP** расширяет карман с 5 до 8 ячеек. Это удобство, а не сила: карман
не даёт статов и не влияет на бой. Выдаётся в панели — карточка игрока или
массовое действие в списке.

Все числа крутятся в панели: **Мир → ♻️ Жизнь мира → 🔒 Инвентарь, потери
и VIP** — размер кармана, прибавка VIP, доля потерь сумки и срок выдачи.
Пустое поле возвращает значение по умолчанию, там же список VIP-игроков.

**Паритет стеков.** Механика работает и в серверном боте: флаг
`InventoryItem.in_stash`, модуль `core/stash.py` с теми же числами и
настройки в **⚙️ Настройки** серверной админки. Совпадение констант
проверяется тестом `test_server_stash.py`.

> Побочно исправлено: массовая выдача VIP писала поле `vip_days`, которого
> не было в модели, поэтому статус не переживал перезагрузку. Теперь VIP —
> обычные поля `is_vip` / `vip_until` и сохраняется как всё остальное.

## 💀 Цена смерти

Поражение стоило 20% золота и телепорта на спавн — неудобство, не более.
Риск ничем не отличался от осторожности. Теперь смерть оставляет след:

- 🪦 **Надгробие.** Потерянное золото не исчезает, а лежит на месте гибели.
  Дошёл обратно — забрал всё; погиб по дороге — потерял окончательно.
  Обычная вылазка превращается в напряжённую, без единой новой механики.
  Чужую могилу тоже можно обчистить, но половина рассыпается прахом.
  Бесхозные истлевают за сутки, и у героя всегда только одна.
- 🩸 **Раны.** После смерти −10% к статам на 10 минут. Лечатся у Лекаря —
  у него наконец появилась работа — или проходят сами. Максимум HP не
  режется: иначе текущее здоровье оказалось бы выше предела.

## 🤝 Отряды

Играть вместе было нельзя: взаимодействие исчерпывалось аукционом и топом.
Теперь до трёх героев ходят вместе — `/invite Имя` или кнопка **🤝 Отряд**.

**Делёж добычи** устроен так, чтобы группа была выгодна, но не превращалась
в станок по печати денег:

| Вместе | Фонд отряда | Каждому |
|---|---|---|
| один | ×1.00 | 100% |
| двое | ×1.30 | 65% |
| трое | ×1.45 | ~48% |

Долю получают только те, кто **в одной локации**, — иначе можно было бы
«возить» друга по миру, стоя в городе. Приглашение требует согласия,
предводительство передаётся при выходе, отряд из одного распадается сам.

Многоцелевой бой, сделанный раньше для катаклизмов (очередь врагов), стал
фундаментом: совместный бой — та же идея с другой стороны стола.

## 🗺 Разведка: достопримечательности

В `data.STORIES` уже лежало 40 описаний клеток — «Древний менгир», «Скала с
рунами», «Заброшенный колодец». Они были чистой декорацией.

Теперь 15 из них — объекты с **однократной наградой**: монеты, опыт,
находка, полное исцеление или благословение (+1 к стату навсегда). Клетка
узнаётся по имени, поэтому старые миры получают диковины автоматически.

Названия в мире повторяются десятками, поэтому настоящая диковина — только
**первая клетка такого имени в локации**: иначе их было бы 156 штук и
ценность пропала бы. Сейчас около 50 на мир, ~10 на локацию.

На карте неизученные помечены ❇️, в шапке виден счётчик найденного.

## 🏰 Мировые боссы

Пожиратель Глубин формально был боссом, но это обычный моб на клетке:
первый добежавший забирал всё.

Мировой босс — **событие, а не клетка**. Он появляется по воле админа,
живёт по таймеру и держит общий счётчик урона:

- бить может каждый, кто дошёл до локации и дорос уровнем;
- награда идёт **по вкладу** — золото, опыт, трофей лучшему бойцу;
- на половине здоровья призывает свиту (используется очередь врагов);
- один босс на мир, в конце — запись в летопись сражений.

Таймеры, вести игрокам и летопись переиспользованы у катаклизмов.
Управление: **Мир → 🌋 Катаклизмы → 🏰 Мировой босс**.

## 🧭 Фракции и репутация

Прогресс был только в уровне и вещах: упёршись в потолок, расти некуда.
Теперь у мира четыре силы с противоположными интересами.

| Сила | Чем живёт | Соперник |
|---|---|---|
| 🛡 Стража Погоста | порядок, упокоенная нежить, выполненные задания | 🌑 Культ |
| 💰 Гильдия падальщиков | добыча, сундуки, мародёрство | 🛡 Стража |
| 🌑 Культ Пожирателя | бедствия и всё древнее | 🛡 Стража |
| ⚜️ Орден Рассвета | свет, охота на нежить, старые клятвы | 🌑 Культ |

**Своим для всех стать нельзя.** Прирост у одной силы автоматически злит
её соперника — репутация это выбор стороны, а не копилка.

Что она даёт:

- **скидка у торговцев** до 25%, но начиная со звания «Знакомый»: иначе
  одна убитая крыса уже меняла бы ценники;
- **реплики жителей** зависят от отношения, а враг фракции (репутация
  ниже −100) получает от её людей прямой отказ;
- **частота катаклизмов**: если культисты перевешивают, беды случаются
  в 1.6× чаще; если стража — в 1.7× реже. Мир реагирует на игроков.

Звания: ☠️ Враг → 😠 Нежеланный → 😐 Чужак → 🙂 Знакомый → 🤝 Союзник →
⭐ Герой фракции. Экран — кнопка **🧭 Репутация** в меню, сводка по всем
героям — в панели, вкладка «Жизнь мира».

## 🕳 Подземелья

Портал был декорацией: админ открывал его, на карте появлялся 🌀, игрокам
уходила весть — а войти было некуда. Серверный бот подземелья умел,
браузерный — нет. Теперь умеют оба.

- **Вход** — кнопка на клетке с порталом, с проверкой минимального уровня.
- **Сетка не хранится**, а восстанавливается из сида забега: сохранение не
  пухнет от сотен клеток, а описание клетки всегда одинаковое.
- Внутри: твари по глубине, сундуки, спуск на нижние этажи. Пройденное
  запоминается, карта этажа показывает только его.
- **Выход** — клетка входа, возвращает ровно к порталу. Гибель внутри
  выбрасывает наружу, как обычная смерть.

Обе панели показывают, **кто сейчас внутри**: прежде чем закрывать портал,
видно, есть ли там живые игроки.

## 🌋 Катаклизмы

Бедствие — временное событие, которое перекраивает мир и меняет правила,
а потом откатывается обратно. Восемь видов: землетрясение, потоп, пожар,
ледяная буря, кровавая луна, звездопад, мор и разлом пустоты.

**Как это работает**

1. Перед правкой снимается **слепок** затронутых клеток (тайл, проходимость,
   моб, сундук). Когда бедствие стихает — само по сроку или кнопкой — всё
   возвращается как было, включая ручные правки админа.
2. Не трогаются: клетки под игроками, спавн и клетки-переходы между
   локациями. Мир не может стать непроходимым из-за стихии.
3. Пока бедствие идёт, действуют множители: частота встреч, урон мобов,
   добыча, золото и эффективность привала.
4. **Тварей становится вдвое больше** (`MOB_MULT`), и они звереют:
   бросаются на игрока из соседних клеток (`ambush`) и сбегаются на шум
   уже идущего боя (`join`). В мирное время оба шанса равны нулю — твари
   смирно ждут, пока на них наступят.

**Агрессия подробнее**

- **Засада.** При шаге по миру тварь с соседней клетки может напасть сама и
  ударить первой. Она уходит со своей клетки в бой, а не поджидает там же.
- **Подмога.** После хода игрока к бою может подтянуться соседняя тварь —
  встаёт в очередь (не больше трёх). Очередь видна в описании боя, награда
  за каждого поверженного начисляется сразу, а клетка освобождается только
  когда добита вся свора. Убежать от своры труднее: каждый в хвосте режет
  шанс побега.
- **Популяция.** Удвоение считается от «мирной» базы и помечается в
  `settings['cataclysm_horde']`, поэтому два наложившихся бедствия не дают
  четырёхкратную ораву, а конец одного не сбрасывает прибавку второго.
  Убитые твари не воскресают, когда беда стихает.

**Где управлять**

| Где | Что доступно |
|---|---|
| Панель → **Мир → 🌋 Катаклизмы** | выбор локации (или всего мира) и срока, живые таймеры, шансы засад и подмоги, лимит и шанс автостихий, летопись |
| Бот → `/admin` → **🌋 Катаклизмы** | быстрый удар по случайной локации и досрочное прекращение |

Право `cataclysms` («🌋 Насылать катаклизмы») входит в ранги *Гейм-мастер*
и *Администратор*; наблюдателю и модератору раздел не виден.

**Автостихии** проверяются на каждом шаге игрока по миру: шанс, лимит
одновременных бедствий и рассылку вестей игрокам можно настроить в панели.
Череда бед воспроизводима — она берётся из сида `cataclysm`.

Игрок видит предупреждение прямо в описании клетки, а кнопка
**🌋 Что происходит?** показывает карточку с множителями и остатком времени.

## 🎲 Сиды мира

Один «Seed» больше не единственный: генерация разложена на шесть
независимых сидов, и каждый можно перекатить отдельно.

| Сид | За что отвечает |
|---|---|
| `terrain` | стены, тропы и форма локаций |
| `stories` | названия и описания клеток |
| `mobs` | расстановка тварей |
| `chests` | где лежит добыча |
| `npc` | места жителей в безопасных землях |
| `cataclysm` | череда бедствий и их размах |

Пока частный сид не задан, он выводится из базового — значит, старый мир
по одному числу воспроизводится точно так же, как раньше. Задал `chests`
вручную — перетряхнул только сундуки, рельеф и мобы остались на местах.
Поля живут в **Мир → Локации → 🎲 Сиды мира**, кнопка «Случайные сиды»
перекатывает все разом.

## 💬 Сообщество: структурированный чат вне бота

Чат живёт в **супергруппе Telegram с форум-темами**: каждый канал — своя
тема, как раздел на форуме. Бот работает мостом в обе стороны.

**Каналы на старте** (`core/community.DEFAULT_CHANNELS`):

| Канал | Доступ | О чём |
|---|---|---|
| 🏛 Общий зал | открытый | знакомства, вопросы, байки |
| 🪙 Торговая площадь | открытый | куплю-продам, лоты аукциона |
| 🤝 Поиск отряда | открытый | зову в подземелье, на босса |
| 📜 Лента мира | только игра пишет | катаклизмы, боссы, порталы, рекорды |
| 🕯 Помощь новичкам | открытый | глупых вопросов не бывает |
| 🍺 Таверна | открытый | оффтоп у очага, шутки, знакомства |
| 📖 Хроники | открытый | отчёты о походах, байки о мире |
| 🏰 Набор в гильдии | открытый | гильдии зовут, вольные ищут дом |
| 🩸 Вызовы на дуэль | открытый | вызовы в Колизей и разбор поединков |

Свои каналы заводятся в панели (**Система → 💬 Сообщество → ➕ Свой канал**).
Ключ можно не заполнять — он соберётся из названия с транслитерацией
(«Ночные Вылазки» → `nochnye_vylazki`): ключ уходит в `callback_data` бота,
где двоеточие служит разделителем, а кириллица раздувает лимит в 64 байта.
Ненужный канал скрывается кнопкой 🙈 — журнал и привязка темы сохраняются.

Плюс **автоматические каналы**: по одному на гильдию (`core/guilds.py`) и
по одному на каждую из четырёх сил. Они не создаются пачкой заранее —
канал появляется, когда его участник впервые заходит в чат, иначе в группе
висели бы десятки пустых веток.

**Источник правды — игра, а не Telegram.** Право читать гильдейский канал
определяется членством в гильдии, а канал фракции — присягой героя. Не тем,
кого админ вручную добавил в тему. Сообщения хранятся в БД игры
(`community_messages`), потому что Bot API не отдаёт историю чата задним
числом, а заявка из «Поиска отряда» нужна внутри бота.

**Что переносит мост** (`bot/community_bridge.py`):

- из игры в чат — реплики игроков, написанные в боте, и события мира
  (подписка на шину `core/realtime`, фильтр в `bot/community_feed.py`:
  порталы, боссы, катаклизмы, рекорды; рутина вроде каждого шага героя
  в общий чат не льётся);
- из чата в игру — сообщения из привязанных тем, подписанные игровым
  именем автора;
- команды прямо в чате (`bot/handlers/community_group.py`):
  `/профиль`, `/гильдия`, `/аукцион`, `/арена`, `/топ`, `/каналы`,
  `/сводка`, `/закреп`, `/поиск <слово>`, `/помощь`.

Часть событий уходит не в общую ленту, а в профильный канал
(`bot/community_feed.EVENT_ROUTES`): лоты — на «Торговую площадь», дуэли —
в «Вызовы», новые гильдии — в «Набор». Событие попадает ровно в один
канал и не дублируется.

**Что умеет чат внутри бота** (меню → 💬 Сообщество):

| Возможность | Зачем |
|---|---|
| страницы истории | канал не обрывается на последних 12 репликах |
| ответы (ветки) | реплика цитирует ту, на которую отвечает |
| реакции | закрытый набор 👍🔥❤️😂🤝; повторный тап снимает |
| закреп | одно важное сообщение всегда наверху канала |
| непрочитанное | в списке каналов видно, где появилось новое |
| тишина | канал можно заглушить, не теряя доступа |
| поиск | по журналу, с учётом прав на закрытые каналы |
| сводка | кто активнее всех и где кипит жизнь |

Реакции и подписки — отдельные таблицы (`community_reactions`,
`community_subscriptions`). Непрочитанное считается как «сообщения новее
отметки о прочитанном», а не счётчиком: сообщения приходят из трёх
источников (бот, группа, события мира), и любой пропущенный инкремент
навсегда разъехался бы.

**Антифлуд** (`core/community.check_rate_limit`, `is_repeat`) считается по
журналу в БД, а не по счётчику в памяти: процесс бота перезапускается
кнопкой в панели, и лимит обязан пережить рестарт — иначе перезапуск стал
бы способом его обойти. Порог намеренно щедрый (12 сообщений в минуту):
задача — срезать пулемётную очередь, а не мешать живой перепалке.
Дословные повторы ловятся отдельно.

**Уведомления.** Кто заходил в канал — получает личку о новых репликах
(`bot/community_bridge.notify_subscribers`). Автору себе не пишем,
заглушённые каналы пропускаем, а права перепроверяются на каждого
получателя: состав гильдии мог измениться уже после подписки.

**Как подключить группу:**

1. создать супергруппу и включить в ней «Темы» (Topics);
2. добавить бота администратором с правом «Управление темами»;
3. в админке открыть **Система → 💬 Сообщество**, вписать ID группы
   (вида `-100…`) и нажать «Создать темы».

Пока группа не настроена, чат работает внутри игры: сообщения пишутся в
журнал, их видно в боте (меню → 💬 Сообщество) и в панели. Мост включается
позже и ничего не ломает.

**Модерация** — на странице канала в админке: мягкое удаление (строка
остаётся в базе для истории), закреп/снятие закрепа, объявления от имени
мира. На главной странице раздела — пульс сообщества: самые говорливые
авторы и самые живые каналы.

## 🎨 Разметка интерфейсов

Бот умеет рисовать экран экипировки: берёт фоновую картинку и приклеивает
поверх неё иконки надетых вещей. Куда именно приклеивать — задаёт
**разметка**, которая рисуется мышью в панели (**Контент → 🎨 Разметка UI**).

**Как это работает.**

1. Выберите сцену — это готовый экран со списком нужных слотов:

   | Сцена | Слоты | Где видно игроку |
   |---|---|---|
   | 🛡 Экипировка героя | оружие, броня, шлем, сапоги, аксессуар | профиль → «🛡 Снаряжение» |
   | 🛡 Экипировка · фракция | те же слоты | тот же экран, но с фоном своей стороны |
   | 🎒 Сумка | 12 ячеек | экран инвентаря |

2. Выберите фон из галереи — это файлы из `admin/static/ui/`. Чтобы
   добавить свой, просто положите туда PNG: он появится в списке сам.
3. Нажмите **«✨ Расставить автоматически»** — панель разложит слоты по
   картинке. Дальше двигайте рамки мышью, угол меняет размер.
4. Панель постоянно показывает, чего не хватает: «не расставлены: helmet,
   boots» или «за краем картинки». Зелёная строка = бот отрисует всё.

**Почему нельзя вписать свой ключ.** Имя слота обязано совпадать с типом
предмета (`weapon`, `armor`…), а ключ сцены — с тем, что ищет бот. Раньше
и то и другое вводилось вручную, и разметка с опечаткой просто не
находилась: экран у игрока оставался прежним, а причину увидеть было
негде. Теперь и ключ, и имена слотов приходят из каталога
`core/ui_layouts.py`.

**Координаты хранятся в пикселях оригинала.** Картинка в редакторе
показывается уменьшенной, но слоты пересчитываются через `viewBox` — на
фоне 1024 px разметка не уедет.

Готовые картинки кэшируются в `admin/static/ui/rendered/` (эта папка в
`.gitignore`). После правки разметки кэш сбрасывается автоматически.

## 🔑 Админка внутри бота и вход в панель

### Те же функции прямо в Telegram

Команда `/admin` (или кнопка **🛠 Админка** в меню) открывает админ-раздел
в самом боте. Разделы показываются по правам игрока:

| Раздел | Что можно | Нужное право |
|---|---|---|
| 📊 Сводка | метрики мира, счётчик админов и порталов | `view_dash` |
| 👥 Игроки | список, карточка, исцеление, предметы, ±золото, ±уровень, телепорт | `view_players` и далее по действию |
| 👑 Доступ | выдать/отозвать ранг, сменить пароль | `grant_admin` |
| 🕳 Порталы | открыть/закрыть портал подземелья | `dungeons` |
| 📣 Рассылка | отправить текст всем игрокам | `broadcast` |
| 📜 Журнал | последние действия админов | любому админу |

Каждое действие проходит проверку права: без него бот отвечает
всплывающим «Нужно право «…»» и ничего не меняет.

### Синхронизация с панелью

И бот, и панель вызывают один слой — `engine/adminops.py`. Поэтому:

- состояние общее (один `Store`), правка из бота сразу видна в панели;
- любое действие пишется в общий журнал `engine/audit.py` с пометкой
  источника (🤖 Бот / 🖥 Панель) — он и есть вкладка **📜 Действия**;
- уведомления игрокам складываются в общую очередь (`outbox`) и уходят,
  как только бот запущен, кто бы ни нажал кнопку.

### Вход в панель без 404

GitHub Pages — статика: серверного маршрута `/admin-login` там нет, поэтому
ссылка из бота раньше отдавала **404**. Прокладка:

```
admin-login/index.html   страница входа — ловит /admin-login?uid=...
admin-login.html         тот же вход рядом с корнем
404.html                 ловит любой неизвестный путь и уводит на нужный,
                         сохраняя ?uid= (учитывает путь /<repo>/ на Pages)
```

Логин — Telegram ID, пароль игрок берёт в боте (`/admin` → **🔑 Логин и пароль**).
После входа `webapp/session.py` поднимает сессию, и панель показывает только
разрешённые разделы; в подвале меню появляется кнопка **Выйти**.

> Вход проверяется по данным в localStorage, значит работает на устройстве,
> где панель уже открывали. Полноценный вход с любого устройства даёт
> серверный запуск (`launch.py`) — там маршрут `/admin-login` настоящий.

| `python3 tests/test_bundle_integrity.py` | бандл не отстал от файлов | если забыл пересобрать бандл |
| `python3 tests/test_parity.py` | реестр механик: новая механика есть в обоих стеках | добавил модуль в `engine/` или `core/` |
| `python3 tests/test_suite_hygiene.py` | сам прогон честен: скипы только по `ImportError`, `random` спинован | добавил новый набор |
| `pip install -r requirements.txt pytest pytest-asyncio` | зависимости обоих стеков | «голая» машина |

Всё выполняется без браузера обычным `python3`. Наборы, которым нужны
`aiogram` / `fastapi` / `Pillow`, на машине без них **не падают**, а печатают
«⚠ Пропуск: не установлены …» и выходят кодом 0 — общий механизм в
`tests/_deps.py` (`require("aiogram", ...)`). `run_all.py` при этом отдельно
предупреждает, что часть сценариев пропущена, и такой прогон не считается
полноценным.

Детерминизм: наборы, использующие `random`, пинят seed — своей константой
каждый (`tests/_seed.py:pin`). Уникальные `telegram_id` для БД берутся мимо
seed (`unique_id()`), иначе повторный прогон по той же базе ловил бы
UNIQUE constraint.
