# Ключ подписи APK

APK в этом проекте распространяется **в обход Google Play** (sideload +
автообновление через GitHub Releases), поэтому для установки обновлений
подпись всех сборок должна быть одинаковой: Android отказывает в обновлении,
если сертификат нового APK не совпадает с уже установленным.

## Что здесь лежит

- `release.key.pem` — приватный ключ в формате PKCS#8 (без пароля);
- `release.cert.pem` — самоподписанный сертификат (действует 10 лет).

CI (`/.github/workflows/android.yml`) подписывает APK этими файлами через
`apksigner sign --key ... --cert ...`. Никаких секретов настраивать не нужно —
первый же релиз соберётся и подпишется автоматически.

## ⚠️ Безопасность

Ключ закоммичен в репозиторий намеренно: это позволяет любому форку и любой
сборке сохранять совместимую подпись. Это нормально для открытого
некоммерческого приложения, которое не публикуется в Google Play, но значит,
что **любой, у кого есть доступ к репозиторию, может выпускать APK от имени
этого приложения**.

Если захотите перейти на собственный секретный ключ:

1. Сгенерируйте новую пару:
   ```bash
   openssl genrsa -out release.rsa.pem 2048
   openssl pkcs8 -topk8 -nocrypt -in release.rsa.pem -out release.key.pem
   openssl req -new -x509 -key release.key.pem -out release.cert.pem \
     -days 3650 -subj "/CN=Shadow Lands Android/O=AlfaGideon/C=RU"
   rm release.rsa.pem
   ```
2. Положите файлы в секреты репозитория (`ANDROID_KEY` / `ANDROID_CERT`,
   содержимое в base64) и поменяйте шаг подписи в workflow, либо просто
   замените файлы в этой папке.
3. **Смена ключа ломает автообновление**: пользователям придётся удалить
   старное приложение и установить новый APK вручную.
