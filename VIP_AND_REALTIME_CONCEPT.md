# VIP и Live-синхронизация — концепция для TG MMO RPG

> Документ отвечает на запрос: расписать идею VIP-преимуществ + синхронизация действий игроков с админ-панелью в режиме онлайн (карта движений, список игроков без перезагрузки, таймеры порталов и живой экономики).

---

## 1. VIP — философия

**Не pay-to-win, а pay-for-comfort.** VIP не должен ломать баланс: игрок без VIP может получить всё то же, просто медленнее и менее удобно. VIP — это уважение к времени игрока.

Текущая реализация: флаг `is_vip` + `vip_until`. Добавлен модуль `core/vip.py` — единая точка проверки `is_vip_active()`. Все бонусы вынесены в константы, чтобы балансить без правки логики бота.

### 1.1 Базовые бонусы (реализовано)

- **Экономика:** золото +50% (`VIP_GOLD_MULT`), опыт +30% (`VIP_EXP_MULT`), сундуки +50% золота, лут +10% качества +5% шанс редкости.
- **Удобство:** быстрый полёт в любую посещённую локацию (обычные — только безопасные), аукцион без комиссии +3 слота, инвентарь +20 условных слотов в UI.
- **Таймеры:** личный трекер сундуков — VIP видит, что сундуки восстанавливаются быстрее (в будущем можно сделать персональную скидку на глобальный таймер).
- **Daily:** ежедневный бонус 200 золота / 100 опыта за вход с активным VIP.
- **Социальное:** иконка 👑 в топах, на карте, в профиле; приоритет входа при техработах (future).

### 1.2 Продвинутые идеи (roadmap)

**Tiered VIP:** Bronze (7 дней), Silver (30 дней), Gold (90 дней / вечный). Чем выше tier, тем выше множители: Gold +75% золота, +50% опыта, +2 слота быстрого доступа.

**VIP-локации и квесты:**
- Отдельная безопасная хаб-локация «VIP-резиденция» с кузнецом, аукционером и ежедневным сундуком.
- Квесты «VIP-контракты» — раз в день дают реликвию.

**Косметика:**
- Цветной ник в чате, кастомный эмодзи-статус.
- Уникальные иконки на карте (корона вместо обычного маркера).
- Скин для клетки игрока.

**Геймплейные удобства (без ломки баланса):**
- +1 попытка переката статов при создании героя.
- Возможность переименовать персонажа раз в неделю.
- Личный лог перемещений (последние 50 шагов).
- Автолут слабых мобов (optional toggle).

**Монетизация:**
- VIP за золото (дорого) + за реальные деньги через Telegram Stars / CryptoBot.
- Подарить VIP другу командой `/gift_vip @username 7`.
- Промокоды от админов.

### 1.3 Баланс-гарантии

- VIP не даёт +урон напрямую, только ускорение экономики.
- PvP (если будет) — VIP-бонусы отключаются.
- Боссы: бонус золота/опыта, но не шанс дропа реликвий.
- Аукцион: VIP не может занижать цену ниже минимума.

### 1.4 Техническая реализация

- `core/vip.py` — `is_vip_active(char)`, `apply_vip_gold()`, `apply_vip_exp()`, `apply_vip_chest_gold()`, `vip_benefits_list()` для админки.
- В `bot/handlers/battle.py`, `location.py`, `dungeon.py` — обёртки вокруг наград.
- В админке `players.html` — badge VIP, в `players_map.html` — корона.
- API `/api/vip/benefits` — отдаёт список преимуществ для фронта и бота.

## 2. Live-синхронизация админки и игры

### 2.1 Проблема до

- Админ видит только логи (battle, visited_cells) или статичные таблицы.
- Карта игроков показывает снимок на момент загрузки.
- Порталы: таймер 2 часа виден только после перезагрузки, игрок не понимает, сколько осталось.
- Экономика: новые лоты появляются только после F5.
- Новые регистрации — только после обновления.

### 2.2 Решение — шина событий `core/realtime.py`

In-memory pub/sub:

- `publish(event_type, payload)` — публикует событие.
- Подписчики — `asyncio.Queue` по одному на WebSocket-клиент.
- Ring-buffer последних 200 событий для первичной загрузки.

**Типы событий:**

| Тип | Когда | Полезная нагрузка |
|-----|-------|-------------------|
| `player_move` | любой шаг, переход между локациями/этажами, travel | character_id, name, location_id, floor, x, y, is_vip, via |
| `player_joined` | регистрация героя | character_id, name, telegram_id, class, level |
| `battle_victory` | победа | character_id, mob_name, gold, exp |
| `chest_opened` | сундук | character_id, location_id, gold, is_vip |
| `portal_opened` / `portal_closed` | открытие/закрытие данжа | template_id, name, location |
| `world_moved` / `world_shuffled` / `world_created` | редактор мира | location_id, x, y |
| `auction_new` / `auction_sold` / `auction_expired` | экономика | lot_id, price, seller_id |

**Откуда публикуется:**

- `bot/handlers/location.py`: move, travel, chest.
- `bot/handlers/battle.py`: victory.
- `bot/handlers/start.py`: player_joined.
- `admin/main.py`: world place/shuffle/create, portal open/close, auction sweep.

### 2.3 Транспорт

- **WebSocket** `/ws/live` — главный канал. При подключении отдаёт историю (30 последних), затем поток. Ping каждые 25с.
- **Fallback polling** — если WS не поддерживается, фронт каждые 5с дергает `/api/live/state`.
- **SSE-ready** — шина не зависит от протокола, можно легко добавить `/api/live/stream`.

### 2.4 Фронт — что меняется

**Карта игроков (`/map`):**
- Подключается к WS, при `player_move` подсвечивает клетку зелёным, обновляет счётчик `👥` без перезагрузки.
- VIP-игроки — корона 👑 рядом с именем, другой цвет точки.
- При `player_joined` — toast «Новый игрок: Name».

**Список игроков (`/players`):**
- Live-добавление строки в таблицу при `player_joined` без перезагрузки.
- При `player_move` — обновляется колонка «Локация» в реальном времени.
- Поиск и пагинация остаются, но новая строка вставляется в начало с анимацией `fadeIn`.

**Порталы (`/editor/dungeons` и дашборд):**
- Таймер 2 часа — живой countdown на JS: берёт `opened_at`, считает `7200 - (now - opened)`, обновляет каждую секунду.
- При `portal_closed` — карточка становится серой, появляется бейдж «Закрывается», без F5.
- При `portal_opened` — новая карточка появляется с анимацией.

**Экономика (`/editor/auction`, `/items`):**
- Новые лоты — live вставка в таблицу.
- Таймер истечения лота (24ч) — живой countdown.
- turnover обновляется.

**Редактор мира (`/editor/world`):**
- Live-индикатор: зелёная точка «LIVE» пульсирует.
- При перемещении локации другим админом — toast и подсветка.

### 2.5 Таймеры без перезагрузки — реализация

```js
function liveCountdown(el, openedAtIso, maxSec=7200){
  const opened = new Date(openedAtIso).getTime();
  function tick(){
    const left = maxSec - Math.floor((Date.now()-opened)/1000);
    if(left<=0){ el.textContent='⏰ Закрыт'; el.classList.add('closed'); return; }
    const h = Math.floor(left/3600), m = Math.floor((left%3600)/60), s = left%60;
    el.textContent = `${h}ч ${m}м ${s}с`;
    setTimeout(tick,1000);
  }
  tick();
}
```

При WebSocket-событии `portal_opened` создаётся новый DOM-элемент с таким таймером.

Для сундуков — аналогично: `chest_respawn_at` отдаётся в API, фронт показывает «восстановится через 12м» live.

### 2.6 Безопасность и производительность

- WS не требует auth в этой версии, но за Real-трафик отвечает RoleMiddleware: только админы видят карту. Можно добавить токен в query `?token=`.
- Очереди ограничены 100 событиями — медленный клиент не завалит память.
- Если игроков >1000 и они двигаются каждую секунду, в шину идёт до 1000 событий/сек. Ring-buffer 200 + drop-oldest в очередях справляется. Для продакшна — вынести в Redis Pub/Sub.

### 2.7 Что дальше

- Добавить карту перемещения в реальном времени внутри локации: видеть точки игроков на сетке клеток, их путь (опционально, с задержкой и с согласия игрока — приватность).
- Live-чат игроков в админке.
- График онлайн в реальном времени (Chart.js + WS).
- Replay: хранить историю перемещений за час и воспроизводить.

## 3. Связка с миром — подуровни

Подуровни (этажи) всегда были в модели (`floors_count`), но визуально не читались:

- На мировой карте: локация с `floors_count>1` теперь — стопка (CSS `box-shadow` слоями) + бейдж `🏢×N`. Всплывает `title` с количеством.
- В редакторе локации: левая панель — вертикальный стек этажей как в Photoshop: каждый этаж — карточка с мини-превью 4×4 и статусом активный/скрыт. Кнопки «Добавить этаж» / «Удалить верхний» дергают `POST /editor/location/{id}/floors/add|remove`, которые используют `worldops.resize` (реальная миграция клеток).
- Лестницы: кисти `stairs_up` / `stairs_down` создают/удаляют переходы внутри одной локации. Визуально — `⬆️` / `⬇️` на клетке, рамка оранжевая. Двусторонность обеспечивается `ensure_stairs`.
- Двери: теперь одна клетка, а не стена. В редакторе — современная кисть «Дверь» с модалкой выбора цели (локация, этаж, x, y). Визуально — `🚪` + зелёная рамка.

## 4. Итог для админа

Админ теперь:

- Видит, где бегает каждый игрок прямо сейчас, без F5.
- Видит регистрацию новых игроков мгновенно.
- Видит, как открываются/закрываются порталы с живым таймером 2 часа.
- Видит экономику в реальном времени.
- Может перетаскивать локации drag-and-drop (любая в любую, обмен местами), перемешивать одной кнопкой, создавать локацию кликом на пустой клетке (модалка вместо перехода в другой раздел).
- Рисует кистью как в современных редакторах: режимы Рисование/Осмотр, drag-to-paint, пипетка средней кнопкой, правый клик — в детальный редактор, подсветка дверей и лестниц.
- Понимает подуровни: на мировой карте стопка, в локации — панель слоёв, лестницы между этажами визуально.

VIP даёт игре монетизацию без ломки баланса и даёт игрокам чувство прогресса.

## 5. API сводка

- `GET /api/live/state` — снапшот (игроки, порталы, экономика, pop, история).
- `GET /api/live/portals` — порталы с `time_left_sec`.
- `GET /api/vip/benefits` — список преимуществ.
- `WebSocket /ws/live` — поток событий.
- `POST /editor/world/shuffle` — перемешать.
- `POST /api/world/create` — создать на сетке.
- `POST /editor/location/{id}/floors/add|remove` — этажи.
- `POST /api/cell/{id}/paint` — расширен: door, stairs, clear_door, erase.

Всё совместимо с текущими шаблонами, требует только `pip install websockets` (FastAPI уже поддерживает).
